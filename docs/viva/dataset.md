## 1. The CICIDS2017 Dataset: Under the Hood

### What is it and how was it made?
The **CICIDS2017** dataset is the academic gold standard for network anomaly detection. It was generated by the Canadian Institute for Cybersecurity (UNB) in a simulated environment that mirrored a real enterprise network. 
* **The Environment**: A victim network (containing workstations, active servers, firewalls, and domain controllers) and an attacking network.
* **The Generation**: Rather than recording raw packets (which contains payload data and is computationally heavy), the raw traffic was processed using **CICFlowMeter**.
* **Flow Extractor**: This utility captures packets, clusters them based on their connection metadata, and aggregates them into **directional network flows**.

### Why are flows better than raw packet capture (PCAP) for ML?
In an enterprise network running at 10 Gbps, parsing raw packet payloads in real-time is computationally impossible for standard hardware. Flow-based representation summarizes thousands of packets into a single metadata record (e.g., duration, byte rate, flag counts), reducing processing overhead by **orders of magnitude** while preserving the statistical patterns needed for classification.

## 2. The Temporal Split: Preventing Data Leakage

```
                       [ 2.8 Million Total Raw Rows ]
                                     │
                     ┌───────────────┴───────────────┐
                     ▼                               ▼
      [ Monday - Thursday ]                     [ Friday ]
      • 1.72M Benign flows                      • 395K Benign flows
      • DoS, Brute Force, Web                   • DDoS, PortScan, Botnets
      • Scaled & PCA-transformed                • Used strictly for Evaluation
                     │                               │
                     ▼                               ▼
         [ Trained Models ] ──► (Inference) ───► [ Zero-Day Validation ]
```

### What is Data Leakage?
Data leakage occurs when information from the target (testing set) inadvertently leaks into the training set, causing the model to learn shortcuts instead of generalized patterns.

### Why does random splitting cause leakage in network data?
Network attacks (like a DDoS or a Brute Force attempt) are not isolated events. They consist of thousands of sequential, rapid flows sharing the same source IP, destination IP, and timing parameters. If you randomly partition these flows (e.g., 80% train, 20% test):
1. The model sees flows from **Attack Session A** during training.
2. The model is then tested on other flows from that **exact same Attack Session A**.
3. It simply memorizes the session's specific IP or timestamp, leading to a false $99.9\%$ test score.

### The Chronological Solution
By splitting the data temporally (Monday–Thursday for training; Friday for testing):
* Friday's attacks (**DDoS, PortScan, and Botnet**) are **completely absent** from the training set.
* This tests the model's true ability to detect **zero-day (novel) attacks** solely based on structural deviations from normal traffic (Autoencoder) or generalized attack profiles (LightGBM).

## 3. Numerical Sanitization: Resolving Division Artifacts

The raw output of CICFlowMeter is chemically noisy. To feed it into ML algorithms, it must undergo sanitization:

### A. The NaN and Infinity ($\infty$) Problem
* **The Cause**: Network flow statistics calculate rates. For example:
  $$\text{Flow Bytes/s} = \frac{\text{Total Bytes Transferred}}{\text{Flow Duration}}$$
  If a connection starts and ends instantaneously (common in UDP queries or TCP resets), the `Flow Duration` is recorded as $0$ microseconds. Dividing any positive number by $0$ yields **Infinity ($\infty$)**. If zero bytes were sent, it yields **NaN (Not a Number)**.
* **The Solution**: The `utils.handle_values()` function is run across all dataframes:
  ```python
  df = df.fillna(0)
  df = df.replace([np.inf, -np.inf], 0)
  ```
  Without this step, these values would cause gradient explosions (weights turning into `NaN` during backpropagation in neural networks) or break split evaluations in decision trees.

### B. Dimensionality Clean-up
* **Duplicate Columns**: Features like `Fwd Header Length.1` are exact carbon copies of other columns and are discarded.
* **Zero-Variance Columns**: Eight columns (e.g., `Bwd PSH Flags`, `Fwd URG Flags`) contain the exact same constant value (usually `0`) for every single row. They carry zero information and are removed to speed up training.
* **Downcasting**: Memory footprint is optimized by converting default 64-bit parameters to 32-bit (`float64` $\to$ `float32`, `int64` $\to$ `int32`), reducing RAM usage from 4GB to under 2GB.

## 4. Scaling & Dimensionality Reduction: The Dual-Path Pipeline

Your project implements two fundamentally different scaling strategies:

```
                            ┌──► StandardScaler ──► IncrementalPCA (69 ➔ 34 Components)
                            │    (Mean=0, Std=1)     (Retains 98.97% Variance)
Raw Sanitized Dataframe ────┤
                            │
                            └──► MinMaxScaler ──► Feature Preservation (69 Raw Features)
                                 (Scaled [0, 1])
```

### Path A: The Supervised Path (StandardScaler + IncrementalPCA)
Used for LightGBM, XGBoost, FFNN, and SVM.
1. **StandardScaler (Z-Score Standardization)**:
   * Translates features so they have a mean of $0$ and a standard deviation of $1$:
     $$z = \frac{x - \mu}{\sigma}$$
   * **Why?**: Principal Component Analysis (PCA) identifies axes of maximum variance. If one feature (e.g., `Flow Duration`) has values in the millions, and another (e.g., `FIN Flag Count`) has binary values (0 or 1), PCA will project all variance onto the duration axis, rendering flag counts invisible. Standardization projects all features onto a uniform scale.
2. **Incremental PCA (IPCA)**:
   * **Why Incremental?**: Standard PCA requires loading all 2.8M rows into RAM to calculate the singular value decomposition, causing memory crashes. Incremental PCA processes the data sequentially in mini-batches.
   * **The Compression**: It compresses the 69 sanitized features down to **34 principal components** while retaining **98.97% of cumulative variance**. This removes multicollinearity (redundancy between features) and accelerates tree-building.

### Path B: The Unsupervised Path (MinMaxScaler)
Used for the Denoising Autoencoder and Isolation Forest.
1. **MinMaxScaler (Bound Normalization)**:
   * Translates features strictly into the range $[0, 1]$:
     $$x_{scaled} = \frac{x - x_{min}}{x_{max} - x_{min}}$$
   * **Why?**: The **Autoencoder's decoder ends with a Sigmoid activation function** to reconstruct the input. Sigmoid mathematically bounds outputs between $0$ and $1$. If inputs were standard-scaled (which yields negative values), the Sigmoid output layer could never reconstruct them, breaking training.
2. **Why PCA is Omitted here**:
   * The Denoising Autoencoder's core task is to learn a compressed representation (through a bottleneck layer of size 16) of the *original* network flow manifold. Pre-applying linear PCA would flatten non-linear manifold geometries, severely reducing the Autoencoder's sensitivity to zero-day deviations.

## 🎯 30 Crux Viva Questions & Answers (Topic 1)

### Q1: What is the CICIDS2017 dataset, and how was it generated?
**A**: It is a benchmark network intrusion dataset containing ~2.83 million flow records across 5 days. It was generated in a simulated enterprise testbed using victim and attacker nodes. The raw packets were captured and aggregated into directional flow summaries using the **CICFlowMeter** utility.

### Q2: What is a network flow, and why do we use it instead of raw PCAP files?
**A**: A network flow aggregates packets into communication sessions defined by a five-tuple (Source IP, Source Port, Destination IP, Destination Port, and Protocol). We use flows because raw packet captures contain heavy payloads and are too computationally expensive to process in real-time. Flow metadata reduces volume by orders of magnitude.

### Q3: What is "data leakage," and how does it happen during random splitting?
**A**: Data leakage occurs when test set patterns are mixed into the training set. In network datasets, attacks span sequential flows. A random split (e.g., 80/20 train/test) shuffles flows from the same attack session into both sets. The model then simply memorizes the session's specific IP or timestamp, giving a fake test accuracy of $99.9\%$.

### Q4: How does your project prevent data leakage?
**A**: By implementing a **Temporal (Chronological) Split**. We train models on Monday–Thursday traffic and test them strictly on Friday traffic. Since Friday's attacks are unseen and occur later in time, the model is forced to generalize rather than memorize.

### Q5: What zero-day attacks did your testing set contain that were completely absent from the training set?
**A**: Friday's test set contained **DDoS, PortScan, and Botnet** attacks. These were completely excluded from the Monday–Thursday training data, forcing the anomaly engine to prove it can identify completely novel threats.

### Q6: Why do NaN and Infinite values occur in network flow datasets?
**A**: Flow engines calculate rate statistics (e.g., bytes/second) by dividing values by connection duration. If a connection is instantaneous (duration = 0 microseconds), dividing by 0 yields **Infinity ($\infty$)** or **NaN** (if bytes sent were also 0).

### Q7: What utility function did you write to handle NaN and Infinite values, and why?
**A**: I implemented `utils.handle_values(df)`, which replaces all `NaN` and `inf` values with `0`. This is mathematically necessary because infinite inputs would cause gradient explosion (weights turning into `NaN` during backpropagation) in neural networks and crash tree splits.

### Q8: What are "zero-variance columns," and why did you remove them?
**A**: Zero-variance columns contain the exact same constant value (e.g., all 0s) for every single row in the dataset. They contain no statistical information. Removing them eliminates redundant mathematical operations and accelerates model training.

### Q9: Give examples of zero-variance columns you dropped from the CICIDS2017 dataset.
**A**: Columns like `Fwd URG Flags`, `Bwd PSH Flags`, `Fwd Avg Bytes/Bulk`, and `Fwd Avg Bulk Rate` had zero variance and were removed.

### Q10: What is duplicate feature leakage, and which column did you prune because of it?
**A**: Duplicate feature leakage occurs when identical columns are feed twice, artificially weighting that feature. I pruned `Fwd Header Length.1` because it was an exact duplicate of `Fwd Header Length` created during flow extraction.

### Q11: What is "downcasting," and what operational benefit did it bring to your pipeline?
**A**: Downcasting converts data types to lower bit representations (e.g., `float64` to `float32` and `int64` to `int32`). It halved the memory footprint of the dataset from over 4GB to under 2GB, allowing standard RAM configurations to train the models without memory crashes.

### Q12: Why does your preprocessing pipeline fork into two separate paths?
**A**: Supervised tree models and unsupervised reconstruction neural networks have conflicting mathematical requirements. Supervised models need zero-centered, reduced-dimension inputs (StandardScaler + PCA) to prevent overfitting, whereas Autoencoders require inputs scaled strictly between 0 and 1 (MinMaxScaler) to match Sigmoid outputs.

### Q13: Explain the mathematical formula for StandardScaler.
**A**: Z-score normalization:
$$z = \frac{x - \mu}{\sigma}$$
It subtracts the mean ($\mu$) of the feature and divides by its standard deviation ($\sigma$), leaving the feature centered at 0 with a standard deviation of 1.

### Q14: Why is StandardScaler crucial before running Principal Component Analysis (PCA)?
**A**: PCA projects data along orthogonal axes of maximum variance. If features are not scaled, a feature with large absolute values (e.g., flow bytes) will dominate the variance calculation over a binary feature (e.g., flags), rendering the smaller scale feature mathematically invisible.

### Q15: Explain the mathematical formula for MinMaxScaler.
**A**: Bounded normalization:
$$x_{scaled} = \frac{x - x_{min}}{x_{max} - x_{min}}$$
It subtracts the minimum value of a feature and divides by its range, mapping all values strictly into the range $[0, 1]$.

### Q16: Why is MinMaxScaler mandatory for training your Denoising Autoencoder?
**A**: The Autoencoder's decoder utilizes a **Sigmoid activation function** in its final reconstruction layer, which mathematically restricts its output values between $0$ and $1$. Bounding the input to the exact same range is required for the reconstruction loss to calculate correctly.

### Q17: Why did you use Incremental PCA instead of standard PCA?
**A**: Standard PCA computes the singular value decomposition over the entire dataset at once, which requires loading all 2.8 million rows into active RAM, causing standard computers to crash. `IncrementalPCA` processes the dataset in memory-efficient mini-batches.

### Q18: How many principal components did you select for the supervised path, and what was the variance threshold?
**A**: I selected **34 principal components**, which successfully retained **98.97% of the cumulative variance** of the original 69 features.

### Q19: Why did you completely bypass PCA on the unsupervised path?
**A**: The Denoising Autoencoder contains narrow bottleneck layers (e.g., size 16) designed to perform non-linear dimensionality reduction. Pre-applying linear PCA would compress the data beforehand, flattening the manifolds and making it highly insensitive to subtle reconstruction anomalies.

### Q20: What is a "manifold" in the context of your unsupervised training?
**A**: A manifold is a low-dimensional topological space embedded within a high-dimensional space. The Autoencoder learns the mathematical structure (the manifold) of normal benign traffic so it can detect deviations from it.

### Q21: What statistical class distribution characteristics did you observe in the Monday–Thursday training set?
**A**: It was heavily imbalanced: Benign traffic accounted for **87.1% (1.72M rows)**, while attacks (DoS, Brute Force, Web Attacks, and others) made up the remaining 12.9%.

### Q22: What attack classes did you group into "Other Attacks" and why?
**A**: I grouped extremely rare attacks like **Infiltration** (36 samples) and **Heartbleed** (11 samples) into "Other Attacks". These classes are too small to train individual classifiers on without causing severe overfitting.

### Q23: What encoding issues did you resolve for the Web Attack labels?
**A**: The raw CSV files contained corrupt character encoding artifacts in labels (e.g., `Web Attack  Brute Force`). I used regular expressions to clean these into clean, standardized labels: `Web Attack - Brute Force`, `Web Attack - XSS`, and `Web Attack - Sql Injection`.

### Q24: Why is training the unsupervised models strictly limited to Benign data?
**A**: If attack flows were included in the Autoencoder's training set, the network would learn how to compress and reconstruct attack patterns as well. By training strictly on benign data, the network only learns the structure of normal traffic, causing unseen attacks to yield high reconstruction errors.

### Q25: Why is standard cross-validation (K-Fold) problematic for temporal network flows?
**A**: K-Fold cross-validation randomly partitions data folds. Like random splitting, it breaks the chronological sequence and leaks future traffic indicators into historical folds, violating the real-world operational assumption that an IDS operates chronologically.

### Q26: Does downcasting numeric features from float64 to float32 degrade model accuracy?
**A**: No. The precision loss is negligible (at the decimal level), whereas the reduction in RAM usage and the boost in computation speed are massive, making it a critical optimization for production pipelines.

### Q27: How does MinMaxScaler handle extreme outliers compared to StandardScaler?
**A**: `MinMaxScaler` is highly sensitive to extreme outliers because a single outlier with a massive value will compress all normal data points into a tiny range (e.g. $[0, 0.01]$). `StandardScaler` is more robust because it centers and scales by standard deviation, though outliers still affect the calculated mean and std.

### Q28: How does the number of features change from raw CSVs to final training parquets?
**A**: It starts at **80+ features**, drops to **69 features** after removing constant, duplicate, and metadata columns, and is finally reduced to **34 components** for the supervised path via Incremental PCA.

### Q29: What file format did you use to store final datasets, and why?
**A**: I used the **Parquet** format (`.parquet`). Parquet uses columnar storage and binary compression, which makes reading and writing datasets up to 10x faster and reduces storage space by up to 80% compared to standard CSV files.

### Q30: If an examiner asks why you didn't use one-hot encoding on categorical features, what is your answer?
**A**: Aside from the target label (`Attack`), the network flow features extracted by CICFlowMeter are entirely numeric and continuous statistical metrics. There were no categorical features in the input data, making one-hot encoding unnecessary.
